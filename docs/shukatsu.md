# 就活タイムテーブル

説明会・ES締切・面接を、大学の時間割のような週表示で並べるページ。
`/shukatsu/` で開く。ホーム画面に追加すると、スマホのアプリとして起動できる。

## 何を解決したいか

就活の予定は種類がバラバラで、置き場所も散らばる。

- 説明会・面接 … 開始時刻が決まっている「予定」
- ES締切・Webテスト … 時刻より「あと何日か」が大事な「締切」

カレンダーアプリに入れると、締切が1日の中の点として埋もれて気づけない。
メモにまとめると、時間の重なり（説明会のダブルブッキング）が見えない。
そこで **週の時間割** と **締切ボード** を1画面に並べ、
「今週どこが埋まっているか」と「次に何が落ちてくるか」を同時に見えるようにした。

## 画面

| 部品 | 役割 |
| --- | --- |
| 締切ボード | 未完了の予定を期限順に並べ、残り日数（あと◯日 / 今日まで / ◯日超過）を出す |
| 時間割 | 縦＝時間、横＝曜日。予定をブロックで置く。空きをクリックするとその時刻で追加 |
| リスト | 週をまたいで全部を日付順に見る。チェックで「提出・参加済み」にできる |
| 種別フィルタ | 説明会 / ES締切 / Webテスト / 面接 / OB・OG訪問 / その他 の表示切替 |
| データの持ち出し | 予定をJSONファイルに書き出す／読み込む |

## 設計で決めたこと

### 保存先を localStorage にした

このページはログインを持たない。ラーメン側と同じ Supabase に相乗りさせることも
考えたが、就活の予定は他人に見せるデータではないので、
共有機能もアクセス制御も要らない。サーバーに置く理由がなかった。

`localStorage` はブラウザにキーと値を保存する仕組みで、タブを閉じても残る。
保存できるのは文字列だけなので、`JSON.stringify` で配列を文字列に直してから入れる。

```js
localStorage.setItem("shukatsu-timetable/v1", JSON.stringify(events));
```

キーに `/v1` を付けたのは、あとでデータの形を変えたときに、
古い形のデータを読み込んで画面が壊れるのを避けるため。

代わりに **端末をまたいで共有できない**（スマホとPCで別々になる）というトレードオフがある。
必要になったらここだけ Supabase に差し替えられるよう、
読み書きは `lib/storage.js` の `loadEvents` / `saveEvents` の2関数に閉じてある。

### ストアに出さず、PWAにした

スマホで「アプリとして」使いたかったが、選択肢ごとにかかるコストが違う。

| 方法 | ホーム画面のアイコン | オフライン | ストア審査 | 費用 | 今のコード |
| --- | --- | --- | --- | --- | --- |
| PWA | ○ | ○ | 不要 | 無料 | そのまま使える |
| Capacitor（WebをネイティブApp化） | ○ | ○ | 必要 | Apple 12,800円/年 | そのまま使える |
| React Native / Flutter | ○ | ○ | 必要 | 同上 | 作り直し |

このアプリは通知もカメラも位置情報も使わない。ネイティブでしかできないことが無いので、
**PWA**（Progressive Web App＝ホーム画面に追加してアプリのように使えるWebアプリ）にした。
審査も年会費も要らず、更新もデプロイするだけで全員に届く。
PWAはCapacitorでネイティブ化するときの土台にもなるので、後から移ることもできる。

PWAに必要なものは2つある。

**1. マニフェスト**（`public/shukatsu/manifest.webmanifest`）
アプリの名前・アイコン・起動時の見た目を書いたJSON。`display: standalone` にすると、
アドレスバーやタブの無い、アプリと同じ見た目で起動する。

**2. サービスワーカー**（`public/shukatsu/sw.js`）
ブラウザがページとは別に裏で動かすプログラムで、ページが出す通信を横取りできる。
これがあると電波が無くてもキャッシュから画面を出せる。

置き場所を `/shukatsu/` の下にしたのは、サービスワーカーの**効く範囲（スコープ）が
置かれた場所より下の階層に限られる**ため。`/shukatsu/sw.js` ならラーメン路線図側（`/`）には
一切影響しない。この都合で、ページ自体も `shukatsu.html` から `shukatsu/index.html` に移した。

キャッシュの方針は2つに分けている。

- **HTMLは通信優先** … 新しいビルドをすぐ反映したいので、まずネットワークを試し、つながらないときだけキャッシュを返す
- **JS・CSS・画像はキャッシュ優先** … Viteがファイル名にハッシュを付けるので、中身が変われば別のファイル名になる。古い内容を返し続ける心配がなく、2回目以降は通信ゼロで開ける

ひとつ落とし穴があった。**初回に開いた時点では、サービスワーカーはまだ通信を横取りできていない。**
登録されて有効になるのはページの読み込みが終わったあとなので、その回のJS・CSSはキャッシュに入らない。
そのまま電波の無い場所へ行くと、骨組みだけあって中身が動かない状態になる。
そこでページ側から「いま読み込んだファイルの一覧」を
`performance.getEntriesByType("resource")` で数え上げてサービスワーカーに送り、
受け取った側でキャッシュに入れている。

### 予定を書き出せるようにした

localStorage は永久ではない。iOSはしばらく使わないとブラウザの保存領域を整理することがあり、
機種変更でも引き継げない。締切が消えると実害が大きいので、
JSONファイルへの書き出しと読み込みを付けた。

読み込みでは、別のファイルを間違って選んだときに黙って全消ししないよう、
形が違えば例外を投げて画面にメッセージを出す。足りない項目は既定値で埋めるので、
後で項目が増えても古いファイルが開けなくなることはない。

なお、書き出すファイル名は半角英数字だけにしている。
日本語を含む名前にすると、ブラウザによっては指定が無視されて
`download` という名前で保存されてしまうため（Chromiumで確認した）。

### 予定を「マス目」に流し込まなかった

最初は時間割どおり「1限・2限」のマス目に入れる形を考えたが、就活の予定は
13:00-14:30 のように30分刻みでない。また説明会が2社重なることもある。

そこで時間を **0時からの分数**（`13:00` → `780`）という数値1個に直し、
列の中で「上から何%・高さ何%」を計算して絶対配置する方式にした。
比較も差分も足し算だけで済むようになり、重なりの判定も数値の比較だけになる。

### 重なった予定を横に分割する

同じ時間に2件あるとき、片方が隠れると意味がない。
そこで「重なっているかたまり」を見つけて、その中で横に等分する。

1. 開始時刻順に並べる
2. それまでの最大終了時刻より後に始まる予定が来たら、かたまりの切れ目とみなす
3. かたまりの中では、空いている一番左のレーンに入れる（終わったレーンは再利用する）

3 を入れているのは、10:00-11:00 / 10:30-12:00 / 11:00-12:00 の3件のとき、
3分割ではなく2分割で足りるため。全部を単純に数えると、重ならない予定まで細くなる。

この計算は `lib/layout.js` の `assignLanes` に切り出してあり、
画面を描かずにテストできる。

### 日付を文字列（"2026-09-16"）で持つ

`new Date("2026-09-16")` は、JavaScript ではこれを **UTC（世界標準時）の0時** と解釈する。
日本時間はUTC+9なので、扱い方を誤ると日付が前日にずれる。

そこで日付は `"YYYY-MM-DD"` という文字列で持ち、Date に直すときは
必ず自分で分解して `new Date(年, 月-1, 日)` の形で作っている（これはローカル時間になる）。
文字列のまま持つと、同じ日かどうかの判定や並べ替えが `===` と `<` で済むという利点もある。

### 8時〜22時の外に出た予定を捨てない

時間割は8時〜22時で描いている。ES締切によくある `23:59` はこの外に出るので、
上部の「終日」帯に時刻付きで逃がしている。表示範囲を24時間に広げると
縦に間延びして肝心の日中が見づらくなるため、範囲は広げずに逃がし先を用意した。

## ファイル

```
shukatsu/index.html            このページの入口（Viteのマルチページ構成）
public/shukatsu/
├─ manifest.webmanifest        アプリ名・アイコン・起動時の見た目
├─ sw.js                       サービスワーカー（オフライン対応）
└─ icon-192.png / icon-512.png / icon-180.png / icon.svg
src/shukatsu/
├─ main.jsx
├─ ScheduleApp.jsx             状態（予定・表示中の週・モーダル）をまとめて持つ
├─ styles.css
├─ data/
│  ├─ eventTypes.js            種別と色の定義
│  └─ sample.js                「サンプルを入れてみる」で入るデータ
├─ lib/
│  ├─ date.js                  日付・時刻の変換と計算
│  ├─ layout.js                時間割の配置計算（重なりの横分割）
│  ├─ agenda.js                締切の抽出と並べ替え
│  ├─ backup.js                JSONファイルへの書き出しと読み込み
│  └─ storage.js               localStorage への読み書き
└─ components/
   ├─ WeekTimetable.jsx        週の時間割
   ├─ UpcomingPanel.jsx        締切ボード
   ├─ EventList.jsx            リスト表示
   ├─ EventForm.jsx            追加・編集モーダル
   ├─ DataPanel.jsx            書き出し・読み込み
   └─ InstallHint.jsx          「ホーム画面に追加」の案内
```

計算を `lib/` に寄せ、`components/` は受け取った結果を描くだけにしている。
画面まわりはテストしづらいが、`lib/` は入力と出力だけの関数なので単体テストが書ける。

## スマホでアプリとして使う

1. スマホのブラウザで `https://ramen-line-map.vercel.app/shukatsu/` を開く
2. **iPhone** … 共有ボタン → 「ホーム画面に追加」
   **Android** … メニュー（⋮）→ 「アプリをインストール」または「ホーム画面に追加」
3. ホーム画面のアイコンから起動すると、アドレスバーの無い画面で開き、電波が無くても使える
